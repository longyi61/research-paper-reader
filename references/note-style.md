# 笔记风格与阅读阶段

## 参考依据

本规范从 20 份 Markdown 阅读笔记中提炼，涵盖文献属性、开头概览、章节层级、核心直觉、方法展开、附录和来源索引。

下述规则可独立执行，无需访问样本目录。样本中的追问内容与首次阅读分开组织；防御性表达按本文件的删改规则处理，不照搬最终笔记的全部结构和措辞。

## 文章组织与密度

- 笔记采用 Obsidian 属性开头：PDF、Citation、journal、paper_type、topic。文件名使用英文论文短标题加年份。具体保存规则见 [markdown-notes.md](markdown-notes.md)。
- 用短概览交代研究问题、主体之间的利益或信息差异、方法与主要发现。发现写出作用方向、机制及真正影响结论的条件。不要将一长串限定词堆进一句话。
- 首次正文固定四个问题。Research Problem 从具体决策情境进入，说明参与者知道什么、决定什么，以及研究价值。Prior Work 解释最接近研究已经解决什么，以及尚未处理的机制；比较对象较多时可用“研究—已有解释—本文增量”表格。
- Core Intuition 用一个与模型一致的场景串起行为变化。先说明谁为何改变决策，再解释其他参与者的反应与最终结果；重点是利益、信息、约束或风险怎样改变。需要区分教学例子时，用“设想”或“例如”自然引入，不追加免责段落。
- Method 先说明主体、信息、时序与目标，再按实际求解依赖组织子节。analytical model 首次即按 [detailed-derivation.md](detailed-derivation.md) 详细展开建模和求解，保留关键代数步骤、候选解、可行域与边界检查，逐项解释符号、运算与经济含义，并将结果接回核心问题。实证论文解释数据、反事实、识别、估计和主要结果，结构论文还要连接行为模型与参数估计。
- 表格用于符号、情形、文献与制度比较；正文承担机制解释。用加粗强调少数关键机制，不把每个段落写成标题加结论的碎片。
- 不设统一字数目标。Method 可以包含多个必要子节，但首次不自动推演每个附录证明或铺开所有延伸问题。

## 初读与追问

最终笔记的长度不能反推首次讲解的范围。analytical model 的核心模型详细求解属于首次 Method；样本中的额外专题、指定命题的完整证明和独立审稿报告按后续请求展开。

首次只回答四个核心问题，analytical model 的必要设定和详细求解均在 Method 中讲清，不另设第五个问题或 Appendix。首次采用审稿人视角时，评价融入相应部分。

用户追问“核心设定有哪些”“逐步推导这个命题”“重新求解修正后的模型”等，才新增相应专题。按用户当前问题确定深度，不能因为存在某个参考文件而自动加载并输出全部内容。已授权保存笔记时，将专题整理进 Appendix，保留完整推导与解释，沿用原文符号和既有编号。

用户后续要求整篇 Critical Review 或 5C 评估时，使用 [critical-review.md](critical-review.md) 的五部分固定模板；这属于追问专题，不改变首次四问题结构。保存时按该文件规定嵌入附录层级。

## 删除防御性和查证式话术

判定一句话是否保留：它是否增加研究事实、机制、数学步骤或影响结果的条件？若唯一作用是防止被质疑，则删除。

以下模式及其同义改写均不进入讲解或笔记正文：

- “这些内容可以从其正式摘要核实。”
- “上述文献定位主要依据本文综述；本次没有逐篇复核所有相关论文的全文。”
- “这是第 4.2 节、第 2991 页解释的关键结果。”
- “这只是一个例子，并不意味着……”“需要谨慎理解……”等没有增加具体内容的补充。
- “以下仅供参考”“不能保证覆盖所有情况”等泛化声明。

处理方式：

| 草稿问题 | 修改方式 |
|---|---|
| 一句话说明结论在某页得到验证 | 删除该句；将具体页码放到来源索引 |
| 文献介绍后补“摘要可核实” | 直接陈述已获支持的具体研究内容，并给必要引用 |
| 用“未逐篇读全文”为宽泛文献结论免责 | 缩小论断到证据支持的内容；需要时补充检索；不输出该免责句 |
| “这只是理论分析，不能直接代表现实” | 删除泛化提醒；若重要，具体写明哪个假设改变了哪项推论 |
| “需要谨慎理解市场覆盖” | 直接解释：“偏好覆盖表示每类消费者都有可选产品；低库存策略下仍会发生缺货。” |
| “仅在一定条件下成立” | 明确写出有关参数、约束或识别条件 |

删除防御句不等于隐藏事实。若缺少某份附录导致无法推导指定命题，直接说明“缺少命题 2 的证明附录，当前只能推导正文给出的步骤”，并尝试获取材料。若识别假设决定因果解释，就把该假设写进研究设计；不能为了语言流畅将相关性改写为因果。

查证与来源对应在内部完成，来源索引提供读者所需的定位。只有在讨论公式、命题或表格本身时，编号才进入分析句，例如“命题 2 的内点解要求数量非负”，不另外添加一条“原文支持此说法”的句子。

## 交付前检查

- 首次正文是否只有四个分析部分，且 analytical model 的 Method 展示了从设定到解的关键计算、成立条件与经济含义？
- 后续附录是否只包含用户实际追问的专题？
- 是否保留了符号解释、机制链条和关键成立条件？
- 是否删除了只为防止质疑的句子以及阅读、核查和工具过程叙述？
- 来源位置是否集中于来源索引，正文引用是否简洁？
- 是否误将参考样本中的后续推导、复算或审稿章节全部带入初读？
