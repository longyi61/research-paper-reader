# Markdown 笔记

开始写入前读取 [note-style.md](note-style.md)，遵循其概览、四个核心问题和后续附录组织方式。

## 保存位置与文件名

用户明确要求 Markdown 文件时直接写入指定路径，不转换成 Page 或其他云文档。

- 完整 `.md` 路径使用原路径；只给文件夹时，采用样本命名方式 `论文短标题 (年份).md`，例如 `Value of Bespoke (2018).md`。使用已核实的元数据，去除非法路径字符。
- 用户要求保存但没有位置时，先沿用当前任务已有目的地或明确项目约定；仍无位置则询问，同时继续整理内容。用于学习风格的样本目录不自动成为保存目的地。
- 未要求保存则在对话中回答，不自动创建文件。聊天无需 YAML 属性。
- 按需创建父目录。目标不可写时遵循工具权限流程，说明具体阻碍，不静默更换目标后报告成功。
- 首次保存遇到同名文件先读取；若无法确认用户要求更新该文件，使用 `_v2` 等未占用名称。更新既有笔记时保留用户批注和其他内容。

## Obsidian 属性

使用样本的字段名称和大小写：

```yaml
---
PDF: "[[PDFs/已核实的论文文件名.pdf]]"
Citation: "作者、年份、完整标题、期刊及卷期页码"
journal: "期刊全称"
paper_type: analytical
topic:
  - 与论文对应的英文主题标签
---
```

以上只是字段示意，交付前填入真实值，删除未知字段和占位。`paper_type` 根据论文使用 `analytical`、`empirical`、`structural` 或其他准确类型；`topic` 用少量稳定的英文小写连字符标签，优先复用目标库中的相关标签。

先核实 PDF 是否确实存在于目标 Obsidian 库。存在时使用库内相对路径的双链；只有 Zotero 附件时记录实际可访问文件路径，不捏造库内双链，不擅自复制或移动 PDF。示例中的 PDFs 目录应替换为实际目录。YAML 字符串正确引用和转义。普通文件夹也可保留这些属性，但使用可访问的实际链接。

## 首次笔记

YAML 后直接给出研究概览，不重复添加论文大标题。概览用连贯短段落说明研究问题与核心摩擦、研究方法，以及主要发现和成立条件。关键发现自然分段，通常二至四项即可，不强凑“三条”。

正文结构：

```markdown
## 1. Research Problem

## 2. Prior Work

## 3. Core Intuition

## 4. Method

## 来源索引
```

四部分下用三级标题组织具体问题。Method 包含必要设定、时序、目标或估计式、求解顺序、主要结果及对应机制。政策、福利、扩展若是理解论文的必要内容，在相应部分简要说明。

首次不增加独立的“核心设定”“详细推导”“审稿判断”“主要结论”或 Appendix；来源索引属于引用材料，不是第五个分析问题。不创建空白附录等待以后填写。

## 后续追问与追加

- 先确认当前论文、用户追问的范围、已有笔记路径与保存授权。已经要求持续整理此论文笔记时，沿用授权更新；仅在聊天中讨论过的论文不会因追问而自动创建文件。
- 先回答本次问题。保存时整理成独立可读的专题，不逐条粘贴问答，也不出现“你刚才问到”“根据上一轮聊天”等叙述。
- 新专题在来源索引之前增加 `## Appendix A 核心设定`、`## Appendix B 基准模型的详细求解` 等，标题只包含实际追问的内容。子节为 `### A.1 ...` 或 `### B.1 ...`。首个专题用 A，之后按已有编号接续。
- 已有相同主题时更新该附录，保留其他附录与正文，避免重复创建。遇到沿用旧格式的笔记，保持原有编号体系。
- 完整保存追问中形成的公式、代数步骤、符号解释、数值例子和经济含义；不得压缩为“推导略”或仅保存最终结果。
- 首次 Method 内必要的假设仍应完整说明；后续“核心设定”附录进一步解释假设为何重要、如何产生机制、改变后会影响什么，避免重复罗列。
- 后续发现原文或初读笔记存在具体错误时，修正受影响的正文、概览和公式；其余内容保留。附录中解释修正的数学依据及结论变化，防止正文与附录互相矛盾。
- 更新同一个来源索引，补充相关原文位置和真正使用的文献，不重复添加多个来源索引。
- 后续 Critical Review 按 [critical-review.md](critical-review.md) 的五部分模板写入同一专题附录；附录为二级标题，内部固定标题降为三级，标题文字保持不变。已有评估时更新原附录，不重复创建。

## 来源、公式与图表

来源索引集中记录原文 citation、DOI、实际版本、可用 PDF 链接，以及笔记各部分对应的章节、公式、命题或表格。补充背景文献使用稳定链接。正文只保留必要的简洁引用，不写核查经过或逐段位置播报。不要添加泛化的“复核范围”“分析归属”免责声明；补充推导和实际复算确需区分时使用简短、具体标签。

公式使用 `$...$` 与 `$$...$$`，多行可用 `aligned`；完整保留符号解释。图表仅在帮助理解且已取得时加入，放在相关解释附近，保留编号和必要图注。图片保存到相邻的专用资源目录并使用相对路径，不依赖临时文件；无需图片时不创建目录。

## 写入后检查

重新读取文件，检查 YAML、链接、四部分结构、数学符号、公式边界与内容完整性。核实库内 PDF 和图片链接存在。检查首次笔记没有擅自增加附录，后续内容对应用户实际追问，同主题没有重复，用户批注未被覆盖。

完成后返回可点击的绝对文件路径，必要时说明更新了哪个专题；不重复全文，不附加技能运行报告。写入失败不得报告已保存。
